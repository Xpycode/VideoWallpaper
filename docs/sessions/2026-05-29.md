## Session: 2026-05-29 (Part 3)

### Goal
Window auto-resize: when sections collapse the window should shrink to fit content instead of leaving large empty gaps.

### Completed
- [x] **Auto-resize mechanism in `MainWindowView`**: added `@AppStorage` observers for all three section expanded keys; on any change, calls `NSWindow.setFrame` with animation (0.2s ease-in-out), keeping the top edge fixed
- [x] **Chrome height fix**: switched from `window.frame.height - contentView.frame.height` (returns 0 on macOS because contentView fills full frame) to `contentView.safeAreaInsets.top` (returns title-bar height ~28px)
- [x] **Window-width-aware tile height**: `computeTargetHeight` now reads `window.frame.width` so the 16:9 display tile height is computed from the actual current width, not a hardcoded 480px
- [x] **All-collapsed verified**: window shrinks to ~127px (3 × 33px headers + 28px chrome) ✓
- [x] **Partial fix**: collapsing all sections works; expanding/collapsing individual sections triggers correct resize in most cases

### Remaining issue (carry forward)
- When **Playlist is collapsed** but another section (Displays or Sources) is expanded, the Playlist section still shows a large empty space
- Root cause: `PlaylistSection` retains `.frame(maxHeight: .infinity)` even when collapsed, filling leftover VStack space
- Latest uncommitted fix in `MainWindowView.swift`:
  - `PlaylistSection` frame is now **conditional**: `maxHeight: .infinity` only when `playlistExpanded == true`; `maxHeight: nil` when collapsed — allows VStack to measure actual content height
  - `GeometryReader` on VStack background measures true content height when playlist is collapsed; `onPreferenceChange` drives resize
  - Expand transition handled separately via `scheduleExpandResize()` with computed min height
  - **Not yet tested by user** — built clean, needs verification next session

### Decisions Made
- Window always resizes to fit content on section toggle (like macOS System Preferences panes)
- Window can still be manually resized; auto-resize only fires on section state changes
- Playlist section is special: needs `maxHeight: .infinity` when expanded (for List scrolling) but not when collapsed
