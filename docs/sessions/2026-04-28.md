### Discovered
- The remote plan's #4 (auto-activate) was **partly already shipped** on this branch: `PlaylistLibrary.autoAssignAllVideosPlaylist` (line 306) and the `videoFoldersDidChange` observer (line 45) auto-sync All Videos when folders change. The "Set Active" wall only stings when a *user-created* playlist exists alongside All Videos.
- Loose video files added via picker or drop need their own security-scoped bookmarks — folders bookmark today but files didn't. Wave 2.2 closed this gap (parallel `videoFilesBookmarks` UserDefaults key, `addFile`/`removeFile`, merged into `loadAllVideoURLs`).
- Project uses manual `project.pbxproj` file references — new Swift files need explicit registration in 4 places (PBXBuildFile, PBXFileReference, group children, Sources phase).
- SwiftUI on macOS 13+ re-exports AppKit and UniformTypeIdentifiers; explicit imports often unnecessary.

### Decisions Made
- Use `.onDrop(of: [.fileURL], isTargeted:perform:)` (macOS 11+) over `.dropDestination(for: URL.self, ...)` (macOS 13+) — gives per-item `[NSItemProvider]` inspection without a custom Transferable.
- Use `loadItem(forTypeIdentifier:)` not `loadFileRepresentation(forTypeIdentifier:)` — the latter copies dropped files into a sandbox temp dir, breaking the path-based identity that `PlaylistItem.folderPath` depends on.
- Auto-activate rule is conservative: only fires when `persistence.assignedPlaylistId == nil`. Active playlists are never silently replaced.
- Used `NSLock`-protected `[URL]` accumulator in `videoDropTarget` for the multi-provider batch — safer than `inout` captured across concurrent `loadItem` callbacks.
