# Session: 2026-01-18

## Goal
Add screen saver / lock screen support to Video Wallpaper app (user feature request)

## Progress
- Researched lock screen vs screen saver feasibility on macOS
  - Lock screen: No public API, only static images possible
  - Screen saver: Fully implementable via `.saver` bundle
- Explored existing VideoScreenSaver sister project (Objective-C)
- Found existing implementation plans in `docs/plans/`
- Decided to add Screen Saver target to VideoWallpaper project (cleaner than bundling separate project)

### Implementation
- Created `VideoWallpaperScreenSaver` target in Xcode
- Set up App Groups entitlement (`group.com.lucesumbrarum.videowallpaper`) for data sharing
  - Main app: Added via Signing & Capabilities
  - Screen saver: Manual entitlements file (bundles don't support capabilities UI)
- Created `SharedDefaults.swift` - wrapper for App Group UserDefaults access
- Updated core managers to use shared container:
  - `FolderBookmarkManager.swift` - folder bookmarks
  - `PlaylistPersistence.swift` - playlist data
  - `VideoPlayerManager.swift` - playback settings
- Created Swift screen saver implementation:
  - `VideoWallpaperScreenSaverView.swift` - ScreenSaverView subclass
  - Reads shared folder bookmarks from App Group
  - Dual-player (A/B) system for transitions
  - Always muted (screen saver requirement)
- Fixed Swift 6 strict concurrency issues:
  - `nonisolated(unsafe)` for UserDefaults static properties
  - `MainActor.assumeIsolated` for notification/CATransaction closures
  - `@preconcurrency import` for ScreenSaver/AVFoundation modules
  - `incomingIsB` flag pattern to avoid capturing non-Sendable AVPlayerLayer in @Sendable closure
- **Build successful** - Screen saver compiles cleanly

## Decisions
- **App Group for data sharing** - Screen saver reads same folders configured in main app
- **Swift implementation** - Cleaner than bridging Objective-C VideoScreenSaver
- **Separate SharedDefaults per target** - Simpler than shared framework
- **Screen saver always muted** - Standard behavior, no audio settings needed
