### Design Decisions
- **Per-display shuffle (Wave 1):** Add shuffle + loop toggle buttons to existing `DisplayCard` control row in NowPlayingView — simple, no layout changes
- **Display arrangement view (Wave 2):** Use "bounding box" approach — each display tile is a container box holding both the proportional screen rect AND its controls
  - Entire arrangement scales proportionally to fit content width (~660pt)
  - Controls (prev/play/next, shuffle/loop) embedded inside each display rect as overlays
  - Handles exotic arrangements naturally — rotated monitor = tall narrow box, stacked = layout grows vertically, everything just scales down
  - Self-contained tiles avoid the "where do controls go" problem for weird arrangements
- Minimum window width (~660pt content area) fits two side-by-side displays comfortably

## Session 8b — User Testing Feedback

### Context
User launched the app and tested all sections. Screenshots captured. Below is the full feedback organized by section, ready for the next implementation round.

### SOURCES Section Issues

1. **Subfolder info missing** — When a folder with subfolders is selected and "Search Subfolders" is on, the UI should show subfolder count and names (unless too many, then just count). Currently just shows the folder path.

2. **Minus button UX** — The `-` button in the header always removes the last-added folder, which is confusing when multiple folders are loaded. **Solution:** Remove the `-` button from the header. Add a per-row delete button (trash icon or swipe-to-delete) on each folder row instead.

3. **Tiny click targets** — The `+` and `-` buttons are very narrow (~2-4px hit area). User had to click the actual glyph, not the general area. Need larger tap targets (at minimum 22x22pt, ideally 28x28pt per HIG).

4. **Duplicate subfolder detection missing** — Adding a main folder AND one of its subfolders doesn't warn or prevent. When "Search Subfolders" is on, that subfolder's videos get scanned twice. Need overlap detection.

### PLAYLISTS Section Issues

5. **"All Videos" tab needs rethink** — Currently serves dual purpose (management + main playlist). Consider:
   - Make it a pure management/browser view — NOT a playlist itself
   - Tree view with expand/collapse by folder
   - Sortable columns: name, duration, resolution, aspect ratio
   - Sort-by-name currently exists but is buried too far down

6. **Resolution/aspect ratio badges** — Pink/colored pill backgrounds look wrong. Per HIG, resolution and aspect ratio should be plain grey text, same font/weight as duration. Not badge-style.

7. **Shuffle/Loop buttons can be removed** from "All Videos" tab — these are playback controls, not library management. They belong in Now Playing or Displays.

8. **Add-to-playlist button per video row** — Each video should have a button to add it to a playlist. Click shows a popover near the mouse with:
   - Existing playlists to choose from
   - "Create new playlist" option
   - If dozens of playlists: "Recent" submenu to keep it manageable
   - Same button on folder rows (add all videos in folder to playlist)

9. **Multi-select support** — Continuous (shift-click) and selective (cmd-click) selection, then right-click or bottom-bar button to "Add selection to playlist"

10. **Empty playlist UX** — When a named playlist (like "MV") is empty, it should be more obvious how to add content. The `+` dropdown with "Add from Library" exists but is buried. Move it to a more prominent position (left side?).

11. **Named playlist keeps current drag-to-reorder** — This is good, keep it for actual playlists.

### DISPLAYS Section Issues

12. **Sync toggle missing from UI** — User enabled "Sync Displays" in an earlier version's DisplaySettingsView. Now that view is deleted and ArrangementView replaces it. But in the screenshot, only single-display "All Displays (Synced)" shows with no way to disable sync. The sync toggle IS in the code (ArrangementView shows it for multi-display) but in sync mode it shows only one display, so the toggle isn't visible.
    - **Root cause:** When sync is on, `allDisplayPlayerManagers` returns 1 entry → `isMultiDisplay` is false → single-display path → no sync toggle shown. **Must always show sync toggle when `NSScreen.screens.count > 1`.**

13. **Sync behavior rethink** — Sync currently collapses all displays into one entry. Instead, still show all display tiles but with a link/sync icon in the corner. Settings apply to all simultaneously. This matches the mockup from the plan.

14. **Display order inconsistency** — In an earlier test, the display order in Displays tab was different from Now Playing tab. Need consistent ordering (probably by `NSScreen.screens` index or by x-position left to right).

### General / Cross-cutting

15. **"All Monitors Synced — Using shared playlist" banner** shows in Playlists tab — this is useful context, keep it.
